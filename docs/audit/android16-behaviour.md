# Android 16 target SDK audit

Baseline `a6bb1d1c4196f13154d3a31505fa316fc2ad48fc` from `completion/prep`. The API 36 branch changes the compile and target SDK, with the existing UI, resources and manifest retained. Phone and API 36 emulator behaviour are **not verified**. File and line references below identify the affected source.

## Toolchain

| Component | Finding |
|---|---|
| AGP and Gradle | The project pins AGP 8.7.3 in `build.gradle.kts:2`, and Build APK pins Gradle 8.9 in `.github/workflows/build-apk.yml:26`. Google lists AGP 8.9.1 as the API 36 minimum and Gradle 8.11.1 as the minimum for AGP 8.9. A supported upgrade is blocked by the workflow constraint. The API 36 branch checks the existing runner combination with the unsupported compile SDK warning visible. |
| Kotlin and Compose | Kotlin and the Compose compiler plugin both use 2.0.21 in `build.gradle.kts:3–4`. Compose BOM 2024.10.01 and Activity Compose 1.9.3 are in `app/build.gradle.kts:59–64`. This SDK-only experiment keeps them pinned. For a later supported AGP/Gradle migration, select a Kotlin version within the published range for that pair and keep the Compose compiler plugin aligned. For example, a proposed stable combination is Gradle 8.11.1, AGP 8.10.x and Kotlin plus Compose compiler plugin 2.2.21. |
| Test libraries | AndroidX JUnit 1.2.1, Runner 1.6.2, UI Automator 2.3.0 and JVM JUnit 4.13.2 are pinned in `app/build.gradle.kts:66–71`. There is no API 36 dependency upgrade mandated by this source audit. Tier 1 runs JVM tests. The existing Tier 3 builds instrumentation and runs on API 35 (`.github/workflows/tier3-full.yml:20–41`). Test library behaviour on API 36 is **not verified**. |
| Release candidate workflow | `.github/workflows/release-candidate.yml:43` still expects target 35. It would reject a target 36 APK at this check. This is separate from the Build APK run. |
